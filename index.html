01 / 研究证据链

结论不是起点。证据链才是。

系统把新闻判断拆成五个可追溯步骤。任何建议都必须能回到原始信息与明确的失效条件。

NewsItem / intake

先判断这是不是同一件事，以及信息是否可信。

系统对 RSS/Atom 新闻做标准化、URL 去重、标题聚类、地区和市场标记，并保留原始来源与发布时间。

  • 来源与时间
  • 可信度评分
  • 去重簇 ID

02 / 实际终端

一套终端，两种研究节奏。

盘中先看方向与待确认点，收盘后再补齐产业、公司和建议证据。

01 / MONITOR

盘中监控

新事件触发短链路提醒，突出方向、置信度和待确认点。

02 / REVIEW

日度复盘

把新闻、事件、产业、公司和建议压缩成可回看的研究摘要。

03 / REPLAY

历史回放

保留每次运行版本，不用今天的信息覆盖当时的判断。

03 / 建议结构

每条建议，都要能被证伪。

方向只是结果。真正需要被记录的是逻辑、催化、风险和什么情况下应当放弃观点。

结构化研究建议

建议由规则引擎收口，大模型只负责增强解释，不能绕过方向门槛或改写动作。

可追溯
ACTION

方向与时效

明确建议动作、有效窗口与当前置信度。

THESIS

核心逻辑

连接对应事件、产业环节和公司业绩弹性。

CATALYST

催化与赔率

记录需要发生的验证信号和目标空间判断。

INVALIDATION

风险与失效

提前写明什么情况出现时必须放弃原观点。

04 / 本地部署

先在本机运行，再接入你的数据。

首次启动不需要市场数据文件，也不要求提供模型 API。真实配置不会进入 GitHub Pages。

本地优先

项目保留 Flask 原生前端和 SQLite 存储，不依赖外部前端服务。

  • Python 3.10 或更高版本
  • 内置演示新闻可直接运行
  • RSS 与 API Key 由用户本地配置

05 / 研究边界

工具可以加速研究，不能替代判断。

News Alpha 以证据、约束和可复现为优先，不承诺收益，也不执行交易。

壹

数据留在本机

RSS 配置、历史观点和模型密钥不发布到展示页。

贰

规则决定方向

模型用于解释和补全，不能越过评分与置信度门槛。

叁

保留证据链

新闻、事件、产业、公司和建议均可反向追溯。

肆

不连接券商

一期只生成研究建议，不自动下单、不管理真实仓位。

伍

不构成投资建议

页面与软件仅用于信息整理、研究辅助和技术演示。
