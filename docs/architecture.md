# 架构与机制

## 设计原则

News Alpha 是本地优先的同步模块化单体。Flask 负责页面和 API，Python 规则引擎负责研究链路，JSON 目录负责产业知识，SQLite 保存用户设置与历史快照。该形态便于个人部署、调试和审计；当采集量增加后，可再把抓取与模型任务拆为队列服务。

## 模块边界

| 模块 | 职责 | 主要文件 |
| --- | --- | --- |
| Web/API | 页面、参数校验、设置和历史接口 | `news_alpha/webapp.py` |
| 新闻入口 | RSS/Atom 获取、自定义源解析 | `news_alpha/news_sources.py` |
| 新闻管道 | 标准化、标题指纹、去重、关键词聚类 | `news_alpha/news_pipeline.py` |
| 研究编排 | 事件、产业、候选、建议和日报组装 | `news_alpha/research_os.py` |
| 事件引擎 | 事件身份、利润传导与产业影响 | `news_alpha/event_engine.py` |
| 知识库 | 事件模板、产业链节点、公司画像 | `news_alpha/catalogs/*.json` |
| 决策层 | 多分析器加权、动作阈值和置信度门槛 | `analysis_registry.py`, `recommendation_manager.py` |
| 数据增强 | 可选技术面、价格和基本面快照 | `technical_provider.py`, `market_fundamentals.py` |
| 模型增强 | OpenAI 兼容接口与受限 JSON 输出 | `model_client.py`, `ai_research_pipeline.py` |
| 持久化 | SQLite 设置、运行版本与历史回放 | `storage.py` |

## 数据流

1. `NewsItem`：来源、发布时间、区域、市场、可信度、标签与聚类 ID。
2. `EventCase`：把已知聚类映射为事件类型、阶段、三情景路径、催化剂和失效条件。
3. `IndustryImpact`：将事件映射到一个或多个产业链节点，记录方向、强度、时长和理由。
4. `CompanyProfile`：按产业链节点召回 A/H 公司，并标记龙头、弹性、主题或弱相关。
5. `StockRecommendation`：汇总事件、技术、市场、基本面、受益程度、风险和执行信号。
6. 工作区快照写入 SQLite，历史版本不会覆盖旧观点。

## 评分与动作

候选初始分由产业链匹配度、事件正负强度和观察池加成组成。最终分对七类分析器做归一化加权：事件 0.40、技术 0.20、市场位置 0.20、基本面 0.15、受益排序 0.15、风险 0.10、执行 0.05。

动作不是模型自由生成。系统先按最终分、公司受益层级和是否在观察池内生成 `买入/持有/观察/卖出`，再通过来源覆盖、证据质量和数据完整度门槛降级高置信度动作。每条输出同时携带理由、催化、风险、失效条件和有效窗口。

## 模型边界

未配置模型时，完整规则链路仍可运行。配置模型后，模型只处理有限结构化输入，并被要求返回 JSON；最终 `action` 不允许被模型修改。模型失败、超时或返回无效 JSON 时，系统保留规则结果并记录运行状态。

## 降级策略

- RSS 全部失败：生成流程回退到演示新闻；手动刷新不会覆盖上次有效缓存。
- 未配置本地行情：价格、估值和基本面标记为缺失，规则链路继续运行。
- AKShare 或第三方接口不可用：技术面回退到 mock，前台显示 provider 状态。
- 大模型不可用：不影响事件映射、评分和历史保存。

## 已知限制

关键词聚类与事件模板目前只覆盖有限主题；未知聚类不会自动获得完整产业链。SQLite 和同步抓取适合个人本地使用，不适合多租户或高并发生产部署。系统不包含券商连接、自动下单、完整仓位风控和经过严格验证的收益预测。
